# 大模型为什么会出现幻觉？

> **一句话：** 大模型的本质是"基于概率预测下一个最像的 token"，优化的目标是语言流畅度与共现似然，而非事实真值；当它缺知识或没有外部检索时，会"编造"以填补空白——这是训练目标、架构机制与数据局限共同导致的，不是程序 bug。

大模型动不动就"一本正经胡说八道"，是它最受诟病的毛病。要治好它，得先搞清楚它**为什么**会这样——这关系到你怎么用、怎么防、怎么评估一个模型。本篇先从定义讲起，再拆成因，最后给一套缓解手段，并和本库其他笔记（[大语言模型概览](/knowledge/llms)、[评测总览](/evaluation/)、[推理模型](/knowledge/reasoning)、[工具调用](/agent/tool-use)、[RLHF 与 DPO](/post-training/rlhf-dpo)）串起来。

---

## 先定义：什么叫"幻觉"

**幻觉（Hallucination）** 指模型生成的内容**表面流畅、语法正确，但事实错误、无依据，或与输入/上下文矛盾**。它和"答错"不同——答错往往是能力边界，幻觉则是"明明没把握，却编得很笃定"。

通常分两类：

- **事实性幻觉**：捏造不存在的实体、数据、论文、引用。例如凭空给出一段不存在的文献 DOI，或把两个真实人物的生平张冠李戴。
- **忠实性幻觉**：回答与给定的上下文、约束或指令相矛盾。例如总结时添加了原文根本没有的信息。

---

## 本质：它是"补全机"，不是"数据库"

理解幻觉的第一性原理：**大模型是一个 next-token predictor（下一个 token 预测器）**。给它一段前缀，它算出"统计上最可能的续写"，而不是"检索到的真相"。

- 训练目标（预训练的交叉熵损失）优化的是"把语料续写像那么回事"，不是"每个陈述都为真"。
- 自回归生成时，模型逐 token 输出，架构里**没有"事实校验"回路**——它不会在写下"某论文发表于 2021 年"后，去数据库核实这句话。
- 推理阶段，它依赖的全部是训练时压缩进参数的"参数化记忆"，以及你给的上下文；一旦两者都缺，它就只能靠共现概率"脑补"。

::: tip 一句话直觉
你喂的是"前缀"，它吐的是"最像的续写"。它像一位永远在即兴接龙、且接得特别流畅的讲述者——流畅不等于正确。
:::

## 成因分层（从根到表）

| 层级 | 成因 | 机制解释 |
| --- | --- | --- |
| **目标层** | 训练目标 ≠ 事实正确 | 预训练最小化 next-token 似然；RLHF 优化"人类偏好"（连贯、有用、无害），而人类评委也常被流畅的谎言说服 |
| **架构层** | 自回归生成无事实校验 | Transformer 逐 token 预测，只建模"上下文相关性"，没有显式的事实存储与验证回路 |
| **记忆层** | 参数化记忆有边界 | 知识封死在训练截止日；长尾/低频事实稀疏；训练语料本身含错误、偏见、虚构内容（互联网噪声） |
| **行为层** | "必须作答"的倾向 | 模型被训练成"有帮助地回应"，倾向于生成内容而非承认"我不知道"，用 confabulation 填补空白 |
| **推理层** | 多步误差累积 | 链式推理中一步错 → 后续基于错误前提继续，幻觉被放大 |
| **解码层** | 采样引入随机性 | 温度 / top-p 提高多样性，也可能固化或发散出错误 |

---

## 三个关键直觉

1. **没有 RAG 时只能靠"脑补"**：纯参数化记忆无法实时获取外部事实，细节题越偏、越新，越容易编造。这也是为什么"检索增强生成（RAG）"被当成缓解幻觉的头号手段——先拿真文档再说话。
2. **"流畅"误导"可信"**：语言越通顺，人类越难察觉错误。这正是幻觉危险的地方：它不像传统 bug 那样报错，而是微笑着递给你一段错的答案。
3. **多步推理会放大错误**：在 Agent、长链路任务里，前一步的小错会被后续步骤当成"既定事实"继续推演，最终离谱结论往往源自一个不起眼的幻觉。

::: warning 一个常见误区
把幻觉当成"模型坏掉了"去打补丁，往往治标不治本。它根植于"预测下一个词"这一根本范式——所以真正的缓解是**改变信息来源与验证方式**（RAG、工具调用、评测护栏），而不是指望模型"更诚实"地凭空答对它不知道的事。
:::

## 怎么缓解（和本库其他笔记呼应）

| 手段 | 做法 | 本库对应笔记 |
| --- | --- | --- |
| **RAG 检索增强** | 先检索真实文档再生成，把"凭记忆"变"凭证据"，并要求引用来源 | 待补（[知识缺口](/knowledge/gaps) 中的 RAG 专题）；当前可理解为"外接知识库" |
| **工具调用 / 实时查询** | 让模型查 API、数据库、搜索引擎，而非凭训练记忆答时效性问题 | [工具调用](/agent/tool-use) |
| **"系统二"慢思考** | 多步自我验证与纠错（见 [推理模型](/knowledge/reasoning)），可大幅压低幻觉率 | [推理模型](/knowledge/reasoning) |
| **约束解码 + 降温度** | 降低随机性；对事实型任务用更确定性解码 | — |
| **评测 + Guardrails** | 建评测集测语义正确性，加防 Prompt 注入与事实护栏，把幻觉率量化出来 | [评测总览](/evaluation/) |
| **对齐训练** | 把"承认不确定"也纳入偏好优化，减少强行作答 | [RLHF 与 DPO](/post-training/rlhf-dpo) |

> 实操心法：**能用检索/工具拿到的，就别让模型凭记忆编**。幻觉治理的优先级通常是：RAG/工具调用（治本） > 推理时慢思考与降温度（治标） > 对齐与护栏（兜底）。
