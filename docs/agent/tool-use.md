# 工具调用（Tool Use / Function Calling）

> 一句话：让模型不仅能"说"，还能"做"——通过结构化协议调用外部函数，拿到真实世界的数据或执行动作。

## 基本原理

模型本身只能生成文本。要让它"查天气""算数据""发消息"，需要：

1. 你向模型**声明一组工具**（名字、参数 schema、描述）。
2. 模型在需要时，输出一段**结构化的调用请求**（如 JSON），说明"调哪个函数、传什么参数"。
3. 你的程序真正执行该函数，把结果**回传给模型**。
4. 模型结合结果，继续推理或给出最终回答。

## 工程要点

- **Schema 要清晰**：参数描述越准确，模型调用越准。
- **并行调用**：一次返回多个工具请求可并发执行，省时间。
- **错误处理**：工具失败时要能重试或换路，别让一次异常卡死整个 Agent。
- **安全边界**：哪些工具"只读"、哪些"会改数据"，要有审批与护栏。

## 常见坑

- 模型"幻觉"出不存在的参数 → 做严格 schema 校验与兜底。
- 长链路里工具结果把上下文撑爆 → 做截断/摘要。
- 多轮里"忘了"之前调用的结果 → 引入记忆机制。
